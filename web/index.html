Car Rental Management System

A native Windows desktop application for managing a rental fleet: add and edit vehicles, search by model, rent and return them with receipts, and track cumulative revenue. It is built with clean OOP design: encapsulation, inheritance, polymorphism and an exception hierarchy.

Required functions

Each function is a single method on RentalAgency, and every rule is enforced in the business layer rather than only in the GUI.

1

Add vehicles

Plates are unique (case-insensitive) and stored in upper case. Only letters, digits and - are allowed. The daily rate must be positive.

2

Edit vehicles

Change the model and daily rate of available vehicles. The plate can never change, and rented vehicles are refused.

3

Search by model

Case-insensitive partial match: cor finds "Toyota Corolla". Only available vehicles are shown, and an empty search lists them all.

4

Rent

Records the renter's name and phone and an agreed daily rate. The rate is pre-filled but can be changed. The status becomes Rented.

5

Return

Charge = agreed rate × days, with a live preview. The charge is added to revenue, the rental is cleared and a receipt is printed.

6

Rentals & revenue

Lists every rented vehicle with renter details and shows the cumulative rental revenue, always with two decimals.

Object-oriented design

The code has three layers. The GUI only calls RentalAgency, and the business layer never shows a window.

GUI layerMainWindow · ModalDialog → AddEditVehicleDialog, RentDialog, ReturnDialog · ReportListView
calls methods ↓   catches RentalException ↑
Business layerRentalAgency → Vehicle → Rental → Renter · Money · Receipt · Validation
through the IDataStore interface only ↓
Persistence layerIDataStore ← TextFileDataStore, InMemoryDataStore

Encapsulation

All data members are private, and objects enforce their own rules: Vehicle::rent() throws if the vehicle is already rented, and Vehicle::edit() throws if it is rented. Money hides its integer cents. Constructors validate, so an invalid object can never exist.

Inheritance

IDataStore ← TextFileDataStore, InMemoryDataStore.
std::runtime_error ← RentalException ← six specific exceptions.
ModalDialog ← three dialogs.

Polymorphism

RentalAgency::loadFrom(IDataStore&) calls the pure virtual load() and save(), and the implementation is chosen at run time. Dialogs use the Template Method pattern through virtual onInitDialog() and onOk().

Exception handling

Business classes throw and the GUI catches. When a value is invalid, the dialog stays open and the bad field is focused. Every operation has the strong guarantee: if it fails, nothing changes.

Value class & operators

Money stores cents in a long long, never a float, so 0.10 + 0.20 is exactly 0.30. It overloads +, *, the comparison operators and <<.

RAII & modern C++

There is no raw new or delete. The code uses std::map, std::optional, a unique_ptr that owns fonts, const-correct getters and no global variables.

Build the desktop app

  1. Install Visual Studio 2022 with the Desktop development with C++ workload.
  2. Clone the repository and open CarRentalSystem.sln.
  3. Select Debug | x64 and press F5.

The project is already configured for C++17, Unicode, warning level /W4 and the Windows subsystem, and it links comctl32. Sample data is copied next to the .exe automatically.

Validation rules

PlateNot empty; A–Z, 0–9 and -; unique, ignoring case
Model / nameNot empty; no | (the file separator)
Rates> 0.00, at most 2 decimals, ≤ 1,000,000.00
Telephone6–20 characters: digits, spaces, -, optional leading +
Rental daysWhole number from 1 to 3650
StatusNo re-renting or editing while rented; only rented vehicles can be returned
